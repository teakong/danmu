danmu 插件示例

当前示例包含访问统计、异常汇报、广告推送插件，可以在 官网 添加飞书、钉钉、企业微信、邮件，把异常和访问记录推送到你的手机上，还可以使用 markdown转html 或 PDF转html 将你的学习资料转化为可推送广告的离线HTML文件收入变现（离线包不用部署服务器，读者打开页面时联网就能收到统计与推送）。

运行方式

下面几种打开方式都可以，任选一种：

  • web 服务器（推荐）：把 danmu 目录当站点根或子目录，访问 /examples/；
  • 静态站点服务器（如 npx serve .）：在仓库根目录启动后访问 /examples/；
  • 本地双击（file://）：例如你辛苦整理的离线文档资料同样能接入弹幕、统计和广告，见 markdown转html；
  • 单独分发某个 html 时，同样也可以统计打开人数、访问趋势以及推送广告，见 offline.html。

插件开发

网页组件（danmu.js）按需加载插件。一个插件就是一个 JS 文件：用 WebsitePusher.registerPlugin 注册一个 run 函数，再在 plugins 里写插件名即可。插件可以上报事件、画自己的界面，或接管收到的消息，全部复用同一条通道码。

运行流程：页面加载加载器 → 读取 plugins / pluginsSite → 加载 pusher → 依次加载插件脚本 → registerPlugin(名字, run) → 执行 run(settings)。不写 plugins 就不加载任何插件，也没有右上角面板，只有挂件默认行为。

组件只加载你点名的插件；settings 是所有插件共用的初始化参数；插件内部抛出的异常会被组件捕获，不会影响挂件主流程。

1. 新建 plugins/mynote.js

(function () {
    if (typeof WebsitePusher === "undefined" || !WebsitePusher.registerPlugin) {
        return; // 组件还没加载，先放弃
    }
    WebsitePusher.registerPlugin("mynote", function (settings) {
        // settings 是 init() / 脚本地址传进来的全部参数，所有插件共用
        console.log("mynote 已启动，通道码=" + settings.channelCode);
        // 上报一条自定义消息，通道后台「推送记录」里能看到 head=mynote
        WebsitePusher.pushTrigger("mynote", "hello 自定义插件");
    });
})();

2. 加载插件

在脚本地址里写插件名，多个用英文逗号分隔；用 init() 时则写 plugins: "mynote"。也可以直接写完整 URL 加载远端插件（注册名取文件名去 .js，如 mynote.js → mynote）：

<script src="static/js/danmu.js?appName=你的应用名&channelCode=你的通道码&plugins=mynote"></script>
<!-- 远端插件：名字写成完整 URL 即可，多个仍用英文逗号分隔 -->
<script src="static/js/danmu.js?appName=你的应用名&channelCode=你的通道码&plugins=https://你的域名/plugins/mynote.js"></script>

远端 URL 插件同样遵守下面的消息流规则：注册名取 URL 末段去 .js 后再判断是否以 msg 开头，例如 https://x.com/msg-foo.js 命中 msg 前缀，订阅完整消息。

3. 消息流：new_msg 与 new_dm

为提升速度，服务端发两种消息，挂件只订阅其中一种，由插件名前缀决定：

插件名订阅事件消息体适用场景
以 msg 开头（不分大小写），如 msg-dialog、msg-sms-codenew_msg完整消息（head + content + uid 等）渲染消息、识别验证码等需要正文的场景
其他名字，如 stat、ad、panelnew_dm轻量消息（head + 头像）统计、广告、弹幕，不需要正文，速度更快

4. 接收完整消息（msg* 插件）

插件名以 msg 开头时，在 run(settings) 里设置 settings.newMsgCallback，参数是解析好的消息对象（不是 JSON 字符串）：

WebsitePusher.registerPlugin("msg-demo", function (settings) {
    settings.newMsgCallback = function (message) {
        console.log("完整消息:", message.content, message.head);
        // 去重：socket 重连可能重复投递同一条消息
        // 不要把收到的消息再用 sendMsg 发回去，否则会无限循环
    };
});

防止死循环：插件收到消息后若调用 sendMsg()，这条消息会被服务端广播回 new_msg，插件再次收到→再次发送→无限循环。务必按消息 ID 和发送内容双重去重。

除回调外，每条完整消息还会派发为 pushNewMsg DOM 事件，页面任意脚本都能监听，无需注册插件；两个插件都要处理完整消息时用它可避免 newMsgCallback 互相覆盖：

window.addEventListener("pushNewMsg", function (e) {
    console.log("收到消息:", e.detail); // 完整消息对象在 event.detail
});

5. 想接管轻量消息，就设置消息闸门

闸门返回 true 表示这条消息由插件处理，组件不再把它渲染成弹幕（ad 插件就是这样把广告画到右下角的）：

var origin = settings.danMuMessageCallback; // 先留住原有闸门
settings.danMuMessageCallback = function (message) {
    if (message.head === "mynote") {
        console.log("收到 mynote 消息", message);
        return true; // 我处理了，不渲染弹幕
    }
    return typeof origin === "function" ? origin.call(settings, message) : false;
};

6. 调试与发布

  • 插件里的异常会被组件捕获，不影响弹幕/统计主流程，调试看浏览器控制台；
  • 按 [网页插件] 过滤控制台，可看到每个插件的加载日志：✓ 表示脚本加载 + registerPlugin + run() 全部成功，✗ 会给出具体原因（未注册 / run() 抛错）；
  • 上报统一用 WebsitePusher.pushTrigger(head, body)，写完可在通道后台「推送记录」里确认；
  • 使用严格 ES5（不用箭头函数、let/const），代码用 IIFE 包起来并判断 WebsitePusher 是否已加载，兼容更多浏览器；
  • 发布：如果使用你自己部署的 danmu.js，把文件放到 danmu.js 同级的 plugins/（线上为 static/customer/js/plugins/），文件名必须与插件名一致，改完记得强刷缓存；
  • 自托管插件：在 init() 里传 pluginsSite，或直接在 plugins 里写完整 http(s)://…/x.js URL（insertNode.js 还支持在 script 地址传 pluginsSite）。

插件 API 一览

API / 钩子说明
WebsitePusher.registerPlugin(name, run)注册插件，脚本加载后执行 run(settings)，每个插件文件调用一次。
settings所有插件共用的初始化参数：channelCode、plugins、pluginsSite、appName 等。
settings.newMsgCallback(message)在 msg* 插件里设置，接收完整消息对象。
settings.danMuMessageCallback(message)轻量消息闸门；返回 true 表示已处理，不再渲染成弹幕。
WebsitePusher.pushTrigger(head, body)上报事件到通道，可在通道「推送记录」里核对。
pushNewMsg 事件DOM 事件，完整消息在 event.detail，可替代 newMsgCallback。
window.sendMsg(text)H5 挂件页（kf-pc.js）提供，发送聊天消息；仅在官方 msg-dialog 插件启用时可调用。注意上面的防循环措施。

常见问题

问题解答
怎么确认插件有没有加载成功？控制台按 [网页插件] 过滤，✓ 全部成功，✗ 给出具体原因（未注册 / run() 抛错）。
插件没加载检查名字拼写与大小写、文件是否在 pluginsSite/名字.js、脚本加载完时是否调用了 registerPlugin。
插件收不到消息正文只有 msg* 插件订阅 new_msg（完整消息）；其他名字收的是轻量的 new_dm，没有正文。
消息一直重复发送插件每收到消息就调用 sendMsg() 会形成回环。按消息 ID 和发送的内容双重去重即可。
两个插件都要处理完整消息怎么办它们共用一个 settings.newMsgCallback，后设置的会覆盖前一个。要各自独立处理，改用 pushNewMsg DOM 事件。

示例页的公共处理

  • 把 WebsitePusher.pushTrigger 包一层，把 visit/click 等上报打到页面下方的「现场日志」，方便确认插件在工作；
  • 日志同时显示组件是否就绪、通道码是否认领成功、上报是否成功；
  • 纯 HTML + 原生 JS，不依赖框架，可整段复制下面的引入代码。
<script src="static/js/danmu.js?appName=你的应用名&channelCode=你的通道码&danMu=0&plugins=stat,panel"></script>
